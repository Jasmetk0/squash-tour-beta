# First actual session Keep → regenerate remaining → review → Adopt → manual Save

2026-10-11. One coherent production-backed slice stacked on integration repair PR #1373. User owns all merges.

## Supported contract

From Run → Players → Generate, first prepare a complete verified 1–128-player initial-cohort preview from the saved World Package, as before. In its read-only complete roster, mark any **nonempty proper subset** of players Keep, choose a **different generation seed** and explicitly **Regenerate remaining**. The API recomputes the source (original seed + exact generation rules, World, Run and Branch), confirms its *exact original pool-preview fingerprint*, validates all selected player IDs against that recomputed pool and passes only those server-resolved player objects as temporary locked inputs to the **existing** `InitialPlayerPoolGenerator.generate`. Unselected places are regenerated by that production kernel.

No client-supplied player data or locked status is trusted. Recreated preserved players retain their source identities, birth dates, attributes, tier, development traits and `source_generation_fingerprint` exactly. After production generation, the temporary `locked` flags are **removed before InitialWorld conversion**: `SeasonActivePlayer.locked_from_initial_pool` remains **false**. Result metadata reports the number of players kept/changed for the *preview*; the emitted summary and generation hash are recalculated on the final unlocked output.

The Run-owned preview remains **nonmutating**, and still requires reviewed source, exact Run/Branch/immutable Saved HEAD, clean Working Draft, World state fingerprint, rederived command/fingerprint before Confirm. A single subsequent explicit **Adopt** stages the recomputed complete InitialWorld component, and only a later **manual Save** creates a Saved Revision. Viewer Branch and source World are never written by preview/Keep.

### Supported limits

- **Only one regeneration pass from a fresh initial full-batch preview.** Another Keep chain needs richer source lineage and Keep semantics, so it is intentionally not yet supported. To restart, generate a fresh initial preview. No hidden fallback or silently reused historic source.
- Keep is **session-only selection**. It is not a permanent player Lock, regeneration lock across seasons, individual editable player, a general Player Package, or a persistent mutable keep-list.
- Selecting Keep never mutates the current review. With a nonempty Keep selection, direct Adopt is disabled until an explicit successful regenerated preview; unchecking all returns to the original preview.
- All players must continue to satisfy the selected hard sport-country / region / 15–45 first-week age conditions and source-world identity. The full batch size remains unchanged.
- New seed must be different, unique sorted IDs are required and may not include nonexistent/foreign players; all-player Keep and empty Keep are rejected as meaningless. Stale source fingerprints fail closed. Conditions and the exact source/keep IDs participate in request and preview fingerprint.
- This slice deliberately does not resolve group overlap, unspecified remainder, permanent locking, Keep multiple regeneration cycles, arbitrary mid-career generation, future knowledge or 0–200 OVR calibration.
