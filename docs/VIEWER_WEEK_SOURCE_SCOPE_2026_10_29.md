# Viewer Week route and source-bound publication guard — 29 October 2026

Scope: read-only canonical Viewer Calendar, Planned Event and Week Detail in `web/src/pages/ViewerRunCalendarPage.tsx`, with focused Vitest regressions.

## Behavior

- Week route coordinates accept any **positive safe integer** rather than assuming a universal 61-week season. The Run's Saved Calendar determines its real events; a week without public content has an empty state. Malformed, zero, negative, fractional and overflow route values never start the canonical readers.
- The selected Product Run, together with the selected Viewer Branch when supplied by the route, bounds each calendar/history/ranking/Finals source. In legacy/test routes without an explicit Viewer Branch, the independently checked Saved Calendar establishes the branch identity used to join public publications.
- Foreign Run/Branch responses are withheld and reported rather than displayed as this Run. A tournament result also must match its Saved Calendar event's **event ID, season and week** before it can be shown as published.
- Query keys include Viewer Branch identity, avoiding reusing an old branch's cached public data after a branch change.
- Week navigation from the season timeline and planned event preserves the exact Saved season in an encoded `?season=` URL. When no active season is known and W occurs in multiple Saved seasons, the Viewer offers exact season links instead of combining historical events and ranking/Finals publications. A nonexistent explicit season fails closed; unknown/malformed calendar years are not inferred from a numeric prefix.
- Within an otherwise matching Finals Race history response, a publication with a foreign Run or Branch identity is rejected individually. Legacy published ranking indices are interpreted against their original 2000-based season system only when the displayed calendar year is resolved.
- The Week Detail's inferred season uses **event weeks plus verified Ranking and Finals Race publication weeks**. A Week with no scheduled tournament can still show its canonical ranking or Finals Race publication; if different seasons contain evidence for the same W, an unqualified W route asks the reader to choose rather than conflating sources. Foreign nested Finals Race records cannot create spurious season candidates. Calendar year to legacy ranking season-index mapping must be unique among Saved season labels.
- Official Ranking publication links are additionally validated against the existing ranking reader's **61-week ordinal contract**: `week_ordinal = season_index × 61 + week − 1`, with valid season/week bounds and an ordinal no later than the published head. Corrupt entries are withheld from both publication links and season inference; a warning explains the missing source evidence. This ordinal rule is intentionally **only** for legacy Ranking publications, not for Calendar Package weeks (such as a future W80).
- Season Calendar overview now exposes **all verified publication-only weeks through read-only, URL-addressable pages of 20** (`?pubPage=2`, and so on). The first page shows the newest weeks, older/newer links preserve navigation to all historical entries, and exact Saved season/week links lead to their verified Ranking and/or Finals Race evidence. The full count and current range are displayed. Missing/invalid/duplicate page coordinates and out-of-range pages show no fabricated entries and offer a safe link back to the latest page. It deduplicates identical publication weeks, omits weeks already containing calendar events, rejects foreign Run/Branch sources and malformed legacy Ranking ordinals, and declines to guess when multiple Saved season labels map to the same year.
- Published tournament matches in the Viewer are joined by **(event ID, Saved season label, season week)**. Duplicate published history rows or indistinguishable duplicate calendar occurrences produce no authoritative champion/runner-up projection rather than picking one arbitrary row.
- A joined published result must also match the canonical Saved Calendar's event name, template, tour/category, host/region and draw/seed/WC/BYE configuration. A matching ID/season/week is insufficient if the sporting metadata differs. Conflicting duplicate history entries are withheld even when one is unpublished; overview counters use only verified joined publications rather than trusting an unverified backend total. An explicit warning notes any omitted published evidence.
- The Planned Event route retains backward-compatible bare event IDs only when exactly one event is found. When IDs are reused, it requires both `?season=` and `&week=` and offers occurrence links; incomplete or mismatched context fails closed. The calendar and week lists preserve these exact coordinates.
- The separate Tournament Detail route accepts only an event ID, so links to it are intentionally withheld for reused IDs; this avoids misleading cross-season navigation until that separate route supports independently verified occurrence context. Duplicate display rows get stable React keys but are never treated as unique sporting sources.

No API/backend/SQLite/command/write/revision or sporting logic is changed, and empty calendars do not invent sporting events. The overview introduces additional **read-only** Ranking History and Finals Race history requests; these are source-scoped to the Saved Calendar. Snapshot, SQLite and native simulation acceptance still require separate real backend tests.

## Test evidence and limitations

Focused mocked-HTTP Vitest cases cover week 80, invalid/overflow week coordinates, foreign Run calendar, foreign Viewer Branch tournament/ranking sources, reused event IDs across seasons, distinct champion projections, exact-context Planned Event links and ambiguous bare links, nonexistent/partial coordinates, duplicate published source evidence, withheld unscoped Tournament Detail links, season-specific Week links, overlapping season/week entries, invalid season query, and a foreign nested Finals Race publication. Additional test cases verify Ranking-only and Finals Race-only weeks, mixed-season public evidence and foreign nested sources. Additional cases verify historically correct `week_ordinal` links, future-head rejection, out-of-range index/week and refusal to infer a season from an inconsistent ranking ordinal. The overview tests now cover Ranking-only and Race-only week navigation, exclusion of weeks already containing an event, foreign Branch rejection, corrupt ordinal rejection, ambiguous Saved season years and 20-entry URL pagination including a second page, invalid/duplicate/overflow/out-of-range coordinates, exact historical Week links and a no-publication state. New metadata regression tests cover mismatched event name, template, host, draw sizes and seeds; Planned Event detail with a mismatching host; overreported published-result totals; and conflicting published/unpublished rows. These are component contracts, not genuine backend, persistence or browser integration.
