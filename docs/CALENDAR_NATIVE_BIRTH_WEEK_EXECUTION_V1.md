# Confirmed native birth Week/Season execution

## Bounded runtime contract

This dependent candidate integrates checkpoint v11 with the existing native Tour
command/preview/explicit-confirmation API. The first due, valid 15th birthday
upgrades the live Tour to `calendar_tour_authority.v3`. It retains an unchanged
v1/v2 root and its real immutable Saved origin. Later natural weeks use the same
writer, including a W → next-season Week 1 boundary and strict horizon extension.
Historical root models and fingerprints are not rewritten.

One `BEGIN IMMEDIATE` transaction owns completed-week development/recovery,
actual birthday profiles, complete missing natural Health weeks, lifecycle,
Official Ranking, public transition event and the command receipt. The complete
new live aggregate is independently replayed before commit. Injected failures
after each stage roll back the whole database. Exact retries authenticate live
state before returning the original result; changed confirmations/requests fail.
Another transition requires a separate ordinary manual Save.

No new sporting mechanics are invented. Development remains annualized by 1/W;
the historical root supplies actual completed-week MatchEngine counts. A genuine
newborn copies its complete frozen 57-attribute profile and receives an empty
Health profile. Existing Health facts are carried without numerical healing.
The existing Signed birth/Entry bridge calculates the ranking from authentic
Edition results and real first Entry, never from nationality or mere birth.
Admin includes admitted identities; future source identities remain absent.
Viewer remains on its immutable Saved publication until manual Save.

## Replay, origin and recovery

Saved loading dispatches v3 explicitly and replays every native receipt against
the actual old root, historically effective policies, prospect source, lifecycle,
Health and checkpoint entry. It reconstructs the exact preview, result, ranking
and public event. Rehashed self-attested command bytes are insufficient: live
origin validation also requires every source revision to be reachable in this
Branch and actually own the command's Tour/checkpoint fingerprints. The first
source independently authenticates the frozen root and Health-prefix length.

Component proof reuse includes v11's additional Tour/lifecycle/Health/prospect
dependencies. An unchanged live Saved owner may reuse that transaction's exact
authenticated aggregate; changed physical bytes always trigger strict replay.
Restore captures all coupled owners and verifies the full post-restore payload
before publishing its revision. This is not a bypass of standalone v11 guards.
Ordinary component Saves and Run-wide horizon extension use the same complete
validation when a v11 owner exists. Extension freezes the old birth clock and
receipts; only a later explicit transition consumes the new horizon.
Source regeneration/deletion protection recognizes actual v4 birthday events,
not only the older legacy lifecycle `origin` marker.

## Deliberate limits

- This v3 supports only natural Week/Season transitions after first birth.
  Edition configuration, Entry, new matches and policy edits after birth remain
  explicitly blocked until their born-player authorities are integrated. Existing
  authentic pre-birth awards may activate/expire normally. A future unfinished
  Edition still blocks progression when due; the writer does not skip it.
- The Run prospect source must remain the same Saved snapshot. More than one
  birthday can be present in that snapshot, but adding/replacing later annual
  cohorts needs immutable historical source epochs. Source rows are not mutated
  into Branch-specific player status.
- Initial Tour creation still requires the existing Saved Week 2+ setup; this is
  not automatic Run initialization, historical initial-cohort generation, numeric
  Health/healing, protected fork re-signing, Full Simulation or release acceptance.
- The older sporting-preflight endpoint remains a read-only component proposal;
  confirmed activation is exclusively the ordinary guarded Tour transition API.
  Its legacy capability labels/UI must not be interpreted as a Full Simulation gate.

## Verification scope

The dedicated HTTP/SQLite tests use the production World, initial Health,
MatchEngine, prospect-source Save, Tour API and immutable Save/restore adapters,
not replacement authorities. They cover Earth W52/O1, FAX W61/O37, W80/O80 with
three-to-five-season extension, and a short W2/O2 actual Season boundary. The FAX
case injects failures at all six write/replay seams and compares full SQLite
dumps. The Earth case rehashes forged receipts and foreign/wrong Saved origins.
A separate real configured Edition case checks actual Entry/awards and played
counts through the birthday. Restart and backward/forward restore remain required.
W80 also extends five to six seasons after the first birthday and advances using
the new horizon. Activated metadata edits/deletions are rejected; a later source
addition cannot be Saved over old birth proofs and its failed Save rolls back.

These are bounded integration scenarios, not the Master full pre-alpha gate or
50×61 certification. Final-head CI must pass before this candidate is merge-ready.
