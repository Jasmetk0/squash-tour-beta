# Native competition after genuine admission

## Versioned authority

A confirmed competition operation after a genuine native birthday upgrades the
Working aggregate to `calendar_tour_authority.v4` and
`calendar_sporting_checkpoint.v12`. A manual Save is required before that first
operation. v4 retains the complete unchanged v3 Tour and its actual Saved origin;
v12 retains the complete unchanged v11 checkpoint. Existing v1–v3 Tour,
v1–v11 sporting, historical match payloads and fingerprints are not upgraded.
The new ordered sporting suffix contains actual tournaments and native weeks.
New tournament evidence uses explicit `calendar_followup_knockout.v6`: its
pre-round snapshot semantics differ from historical sequential v5. Historical
v5 remains on its old reducer, which refuses v6.

The same Edition, valid application submission, frozen ranking binding, production
Entry field resolver, seeding/draw builder and Edition points are used. Application
eligibility comes from the authoritative current lifecycle, including admitted
players and excluding future prospects/retirees. Birth itself grants neither
first Entry nor points. Genuine Entry is adopted by the existing next-week
lifecycle/ranking bridge. Policy changes after admission remain unsupported;
the historical policies remain effective. No new sporting rule is introduced.

## Actual match inputs

The original rally MatchEngine consumes the actual current 57 attributes,
form/sharpness/load and participant-ordered current Health. Both semifinals
(or all quarterfinals) consume the same frozen pre-round population and source
fingerprint. Actual winner identities and post-match effects feed the next round.
No recovery is inserted between rounds. Unaffected players retain their records.

There is no replacement InitialWorld and no borrowed player profile. Initial
players retain their authentic biography. An admitted prospect uses its Signed
birth/lifecycle provenance, source display name/country and current canonical
sporting record. Its source does not contain the legacy play-style/archetype or
HiddenCareerTraits DTO; the compatibility input explicitly records `unspecified`
style/archetype and null legacy career traits. The existing MatchEngine's
unspecified-style fallback applies; no career traits, nationality DNA or new
style-generation rule is invented. Hidden traits are not used by this match
engine. Canonical 57→engine projection and its existing calibration remain.
These missing legacy fields are an explicit compatibility limitation, not a
claim of a newly generated full biography.

Confirmed results use actual completed matches and the pre-existing Edition
point table. The next native Week/Season Transition counts every actual match
in the completed week and develops/recovers the full admitted population using
the existing annualized 1/W kernel and unchanged weekly fatigue rules. Signed
season summaries/records consume frozen participant identities from the actual
played receipt, without adding profiles to InitialWorld.

## Commands, integrity and recovery

Existing exact HEAD/checkpoint/Tour preview, explicit confirmation and one
`BEGIN IMMEDIATE` transaction remain authoritative. Configuration/application/
approval/draw may share a Working Draft. Play, result confirmation and transition
require their actual preceding Saved aggregate. All operations remain unsaved
until separate manual Save; Viewer continues on immutable Saved publication.

Saved loading independently reconstructs every new command preview/result,
Edition/Entry/draw change, actual MatchEngine result and log, weekly sporting
suffix, Health/lifecycle, ranking and public event. Rehashed self-attested bytes
are insufficient. Every source must be reachable in the actual Run/Branch and
own its declared checkpoint; sporting commands additionally require the exact
Saved Tour. The historical root and effective calendar/horizon must really exist
in their referenced Saved sources. One unchanged Signed prospect source remains
required; historical source epochs are not added.

The complete new live aggregate is independently verified before commit. Late
write/replay faults roll back the whole transaction. Exact retry authenticates
current authority before returning the original receipt; changed requests or
consent fail. Restore captures and authenticates all coupled live owners before
publishing. Extension preserves old clocks/payloads and only explicit subsequent
commands consume the extended horizon. Post-admission historical match replay
requires its actual Saved competition owner and replays frozen Health/inputs;
pre-birth replay retains its independent historical adapter.

CS/EN Admin exposes actual competition capability and sporting-Save readiness.
Runtime capability is explicitly `native_tour_transition_readiness.v2`; v1
responses remain understood as the older natural-transition-only capability.
HEAD/input/generation and A→B→A stale-response guards are retained. The old
component-only birth preflight is hidden after admission. Full Simulation is not
unlocked.

## Verification and deliberate limits

The dedicated real HTTP/SQLite matrix uses small production-created populations,
a Signed admitted player plus a still-future prospect, actual Edition/Entry/draw/
MatchEngine, confirmed points, played counts, independent manual Saves, restart,
backward/forward restore, exact replay/retry and negative scope/history checks.
Earth W52/O1, FAX W61/O37 and W80/O80 extension are separate mandatory cases.
The FAX case injects late match/Tour/replay failures and compares complete SQLite
dumps. Real Chromium exercises the newly enabled Admin operation chain and
unchanged pre-Save Viewer. Mocked frontend tests are component tests only.
Existing full native Tour/season API and W52/W61/W80-1000 browser gates remain
mandatory; their original assertions/timeouts/selectors are retained.

Final-head evidence must pass before this candidate is presented as merge-ready.
The new gate is bounded development acceptance, not a full release/50×61 run.
Historical prospect-source epochs, numeric Health/healing, protected forks,
post-admission policy editing, cross-Edition simultaneity and remaining Master
pre-alpha requirements are still unsupported. Existing 4/8-player full ranked
main-only executor limits remain. Master product decisions are unchanged.
