# Five-season stress scenario: requested v2 capabilities vs authentic compatible run

**Draft PR #1820 — 16 November 2026. No five-season success is claimed until a real
final-head Actions run completes. No sporting rule, historical schema or production
simulation engine is changed by this experiment.**

This scenario intentionally has **two different profiles**. Their results are never
merged into one "successful" claim.

## Profile A — requested target, intentionally capability-gated

The exact requested workload, generated by
`python scripts/giant_native_five_season_load.py --profile requested --plan-only`,
is a deterministic **planned specification**, not a played match history:

| Dimension | Target |
| --- | --- |
| Run | 5 simulated 52-week seasons, 260 positions; 6-season horizon only for fifth closure |
| Population | 1,000 initial players, 80 further prospects/season = 400 signed arrivals over 5 seasons |
| Birth distribution | Four waves/season, 20 per wave when using the default 80 |
| Event inventory | 60 ranked Editions per season; **300 across five seasons** |
| Primary weeks | One Edition every week 4–50 |
| Concurrent weeks | Additional Editions in W8,12,...,48 and one additional in W44 |
| Season finale | One **128-main World Championship in W51**, each season |
| Main field sizes | **16 / 32 / 64 / 128** |
| Ranking tiers | Synthetic regional (100), challenger (250), international (500), major (1,000), elite (1,500), selected side events (125–225), world (3,000) |
| Qualification | Some events have a separate 16- or 32-player Qualification, four qualifier places; world main128 + Q32 |
| Match counts | The JSON plan includes the minimum expected real Main + Q matches, assuming a fully played no-WO bracket; not a measured result |

**These points are benchmark fixtures, not new approved FAX/ATP ranking tables.**
Qualification participants, decisions, Draw and real winners must eventually come
from authentic existing source-bound authorities; mere planned fields do not
constitute sporting results. The 80 arrivals are signed to the ordinary native
prospect-source authority in four waves: S1 W3/15/28/41; S2+ W2/14/27/40.
Their actual professional status is determined by the stored lifecycle, not
fabricated by the workload.

### Known native compatibility boundary

The current configured native Tour v2 Global Slot runner uses actual full Main
knockout rounds for 4/8 entrants; its `CalendarFollowupKnockout` is limited
to 4/8, and historical v2 fields cannot become a canonical Q/Main Saved Draw
by changing `main_entrant_count` or the point table. Main sizes 16–128 and
Qualification are **unsupported by this executor**.

Native v4 has source-bound Q/Main and larger bracket support for specific
reviewed source geometries, but separate Saved Calendar/Entry/Draw bindings,
announcement/schedule, Turn Pro eligibility, awards and W-clock guards apply.
The reviewed Ranked Q/Main path specifically has W61 conditions; this is a
W52 experiment. No proof currently shows that arbitrary new 16/32/64/128 + Q
W52 ranked Editions can be invented and played through that path.

`unsupported_execution_capabilities()` reports blockers for the requested
profile. Attempting to execute it writes an explicit **unsupported** summary
and exits nonzero, instead of falsely counting simulated tournaments.
**Therefore the requested-profile end-to-end hours cannot be measured yet.**

## Profile B — genuine executable *compatibility baseline*

To obtain performance data without lying about the sporting capabilities, the
independent `--profile compatible` version keeps:

- 5 × 52-week Run clock, 1,000 initial players, 80 prospects per season in four
  signed waves; actual Week/Season Transitions and explicit Saved Revisions
- 60 ranked Editions/season and actual 300 played attempts across five seasons,
  including simultaneous independent fields where the calendar overlaps
- Real production HTTP, SQLite, Entry submissions, approvals, Draw, MatchEngine
  via next global Simulation Slot, result confirmation and signed season archive
- Distinct deterministic point values and real four-/eight-player brackets only
- One **eight-player World-Championship-labelled compatibility surrogate**
  in W51 instead of the requested authentic 128/Q32 World Championship

The compatibility profile deliberately has **NO Q** and only 4/8-sized Main
draws. Its performance is *not* an extrapolated full 16–128+Q tournament
performance. Larger fields and qualification require separate implementation,
validation and later re-run of Profile A.

Each same-week tournament field is disjoint, and the global-slot loop runs
all scheduled real matches; no player appears in two simultaneous Editions.
The signed prospect source is immutable, and only actual weekly native intake
can activate newcomers. Entry remains restricted to signed eligible initial
professionals for conservative compatibility, not artificially promoted minors.

## CI behaviour and limits

Workflow: `.github/workflows/giant-native-five-seasons.yml`.

- Triggers: only new experiment paths on PR, plus explicit manual dispatch.
  This Draft PR is isolated from other PR source files and Fast CI test suites.
  GitHub may not recognise a **new workflow** for dispatch until it is present
  on the repository default branch; check actual Actions status, never infer
  an automatically started benchmark from the PR's creation.
- Fast plan-contract tests check all requested sizes, exact point-stage keys,
  300 unique Editions, 5 championship plans, Q counts, 80×5 arrival profile,
  and the fact that unsupported parts are truthfully blocked.
- Heavy job runs ONLY `--profile compatible`: separate runner and concurrency
  group, `315` minute internal budget, `350` minute job timeout.
  This is not the ordinary required merge check, does not cancel other PR jobs,
  and writes only to disposable runner paths.
- **Shared GitHub Actions account quotas still apply:** an independent workflow
  can queue other jobs or consume hosted billing/minutes. Isolation guarantees
  no shared source/DB writes or concurrency cancellation, **not zero cost**.
- Artifacts: `summary.json`, `timeline.jsonl` and console log on pass/fail.
  The SQLite database itself is not uploaded; metrics retain no raw confidential
  world profiles. Each completed week and season has an actual duration,
  population count and SQLite/RSS measurement. Budget termination is NOT pass.

No remote execution result, success, duration in hours or completed World
Championship is claimed in this document. The 5-season actual baseline may
exceed the budget, especially as Saved revisions grow. Failures and limited
later-season evidence should inform the next optimization task.

## Reproduction (from repository root)

```bash
PYTHONPATH=src:. python -m pytest -q tests/application/test_giant_native_load_plan.py
python scripts/giant_native_five_season_load.py --profile requested --plan-only
python scripts/giant_native_five_season_load.py --profile compatible --plan-only

# Only existing supported 4/8 Main: actual HTTP/SQLite + 80 prospects each year.
PYTHONPATH=src:.:tests/api python scripts/giant_native_five_season_load.py \
  --profile compatible --seasons 5 --players 1000 \
  --editions-per-season 60 --born-per-season 80 \
  --budget-minutes 315 --output-dir /tmp/giant-compatible-load
```

The benchmark refuses to overwrite a previous SQLite run. To do another
run, use a new empty output directory.
